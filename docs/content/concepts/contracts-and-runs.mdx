# Versions, projections, and Runs

## `GraphVersion`

A `GraphVersion` is an immutable delta with parent versions, added or retired Resources and Statements, a source revision, and a validation receipt. A branch GraphView points at one head version.

The receipt is the durable handoff boundary. When asking an agent to implement a design, identify the exact version.

## Projections

Implementation plans, verification reports, and fix lists are query projections from a resolved view. They are meant for humans and coding tools.

They are not canonical inputs. Editing a projection does not mutate the graph. Publish an explicit proposal through a graph session when product intent changes.

## Missions and Runs

A Mission is a persona-specific executable verification contract. A Run records normalized adapter events and its HarnessResult. Each Mission Run receives its own session and does not publish implicitly.

That isolation matters: one persona’s successful path must not approve another persona’s permissions or recovery behavior.

## Legacy run files

Files from the pre-transactional workflow may remain in a repository for history. Production commands do not select, mutate, or authorize them. See [migrate from legacy runs](/reference/run-json-schema).
