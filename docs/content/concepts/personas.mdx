# Personas and Missions

An **Actor** is a role with authority in the product: member, administrator, approver, guest, operator. A **Persona** is a concrete perspective that can assume an actor while carrying goals, constraints, context, and risk.

Several personas may share one actor. A new user and an expert operator can both be members while needing different discovery, error, and recovery paths.

## Relevance

Lamina compiles a Mission for every Persona connected to the workflow’s actor and operation closure. There is no fixed maximum. Relevance comes from graph relationships, not from picking a convenient sample of three.

## Independence

Each Mission:

- resolves the same workflow version;
- gets persona-specific goals and constraints;
- runs through an adapter capability manifest;
- stages normalized events and evidence in its own session;
- requires explicit publication.

## Evidence boundary

Persona simulation is `simulated`, not `runtime_evidence`. A Mission can identify an expected failure before the product is run, but only normalized adapter events can support a runtime proof.

`.lamina/personas.json` is an evidence input used to propose Persona Resources. The canonical Persona graph lives in Ladybug.
