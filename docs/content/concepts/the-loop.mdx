# The product loop

```text
install → initialize → design → publish GraphVersion → implement → verify → fix or redesign
```

## Initialize

`/lamina-init` establishes the product boundary, actors, and relevant personas. On brownfield projects it first observes what exists; on greenfield projects it records explicit assumptions and gaps.

## Design

`/lamina-design` stages Resources and Statements in a graph session. Validation checks structure, reachability, authorization, contradictions, proof readiness, and evidence freshness. Publication returns a `GraphVersion` receipt.

## Implement

The coding agent consumes a projection resolved from that version. The projection is a convenient handoff; it does not become canonical graph state.

## Verify

`/lamina-verify` compiles an independent Mission for every relevant Persona and runs each in isolation. Normalized runtime events become evidence. A Run is staged until its session is explicitly published.

## Decide the next edge

- Implementation differs from a valid contract: fix the product and verify again.
- Verification reveals missing product intent: return to design and publish a new version.
- Source changed: refresh observations and check evidence staleness.
- Another writer moved the graph head: rebase the session and review the semantic diff.

The loop is complete only when the relevant workflow validates and its proofs have current evidence.
