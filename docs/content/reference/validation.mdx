# Validation and approval

```bash
lamina graph validate
lamina graph validate --scope workflow.password-reset
```

## `ok`

`ok` answers whether the graph is structurally publishable. Invalid references, illegal literals, duplicate workflow positions, protected status spoofing, and other schema failures make it false.

Publication with `ok: false` fails atomically with `LAMINA_VALIDATION_FAILED`.

## `approved`

`approved` answers whether the structurally valid view is ready. It becomes false when active contradictions, stale evidence, or readiness gaps remain.

A valid but unapproved version may still publish so drafts and unresolved decisions remain inspectable. Consumers must check the receipt instead of equating “published” with “ready.”

## Scoped validation

Whole-view validation covers everything active in the view. `--scope` follows Statements connected to one Resource and validates that affected closure.

Use scoped validation for implementation and Mission compilation. Use whole-view validation for release readiness.

## Determinism

Validation is engine-owned and deterministic. Agents cannot submit `approved: true`, change epistemic class, or select a privileged socket method to bypass policy.
